# SkillForge — سند بیزینسی MVP

**محصول:** SkillForge  
**نوع:** Standardized Skill Assessment & Mock Interview Platform  
**افق MVP:** حلقه کامل «ثبت‌نام → رزرو → ارزیابی → کارنامه قابل‌اثبات» بدون پرداخت و بدون UI کامل

---

## ۱. مسئله (Problem)

کاندیداها برای اثبات مهارت معمولاً به یکی از این‌ها وابسته‌اند:

- خوداظهاری در رزومه / لینکدین (قابل اعتماد نیست)
- آزمون‌های آنلاین عمومی (از مصاحبه واقعی فاصله دارد)
- مصاحبه آزمایشی غیرساختاریافته (خروجی مبهم، غیرقابل‌مقایسه، غیرقابل‌اشتراک)

نتیجه: کارفرما و خود کاندیدا سیگنال استاندارد و قابل‌تأیید از سطح مهارت ندارند.

---

## ۲. راه‌حل MVP (Solution)

SkillForge در MVP یک **جلسه مصاحبه آزمایشی زمان‌بندی‌شده** با **Scorecard استاندارد** ارائه می‌دهد و خروجی را به‌صورت **ScoreRecord غیرقابل‌تغییر** ذخیره می‌کند که با لینک عمومی قابل verify است.

ارزش یک‌جمله‌ای:

> «یک مصاحبه واقعی، با نمره استاندارد، که بشود لینکش را فرستاد.»

---

## ۳. کاربران و Jobs-to-be-Done

| Persona | Job اصلی در MVP | موفقیت برای او |
| --- | --- | --- |
| **Candidate** | مهارت را در یک جلسه واقعی بسنجد و خروجی قابل‌اشتراک بگیرد | کارنامه با OverallScore + Verdict |
| **Interviewer** | زمان آزاد اعلام کند و با قالب ثابت ارزیابی کند | اسلات رزرو شود؛ scorecard یک‌بار submit شود |
| **Admin** | کاتالوگ مهارت را تمیز نگه دارد | approve کردن مهارت‌های پیشنهادی |
| **Verifier (عمومی)** | صحت نتیجه را بدون لاگین ببیند | صفحه/پیلود verify فقط‌خواندنی |

خارج از MVP به‌عنوان مشتری مستقیم: کارفرما سازمانی، آژانس استخدام، پرداخت‌کننده B2B.

---

## ۴. محدوده MVP (In Scope)

فقط قابلیت‌هایی که حلقه ارزش را کامل می‌کنند:

1. **هویت:** ثبت‌نام/لاگین Candidate و Interviewer
2. **پروفایل:** مشاهده/ویرایش پروفایل و مهارت‌های خوداظهاری / تخصص interviewer
3. **مهارت‌ها:** جستجو، پیشنهاد مهارت جدید (`IsApproved=false`)، approve توسط Admin
4. **زمان‌بندی:** interviewer اسلات UTC بسازد؛ candidate اسلات آزاد را ببیند
5. **رزرو امن:** یک اسلات فقط توسط یک نفر؛ بدون double-book
6. **ارزیابی:** interviewer یک‌بار scorecard + feedback + verdict ثبت کند
7. **امتیاز:** محاسبه OverallScore با فرمول ثابت محصول
8. **اثبات:** تاریخچه کاندیدا + لینک verify عمومی روی booking

### جریان ارزش

```text
Signup → Profile/Skills → Create or Find Slot → Book → Submit Scorecard → ScoreRecord → Public Verify
```

### فرمول امتیاز (قانون محصول MVP)

- `SkillScore = (Average(ProficiencyLevel) / 4) * 100`؛ اگر مهارتی نباشد → برابر VerdictScore
- `VerdictScore` از enum: NoHire=15، LeaningHire=50، Hire=75، StrongHire=100
- `OverallScore = round(0.7 * SkillScore + 0.3 * VerdictScore)` در بازه 0–100
- بعد از submit: `Scorecard.IsLocked = true` و `Booking.Status = Completed`
- `ScoreRecord` فقط‌افزودنی است (دستکاری بعدی ممنوع)

## ۵. خارج از محدوده MVP (Out of Scope)

- پرداخت، کیف پول، کمیسیون، قیمت‌گذاری جلسه
- ویدئوکال داخل پلتفرم (MVP فقط `MeetingLink` خارجی مثل Meet/Zoom)
- اپ موبایل native
- UI کامل Blazor محصولی (Swagger برای تست MVP کافی است؛ UI فاز بعد)
- مارکت‌پلیس پیشرفته جستجو/رتبه‌بندی interviewer
- سیستم اعتراض به نمره / بازبینی ثانویه
- نوتیفیکیشن ایمیل/SMS پیشرفته
- تقویم Google/Outlook sync
- چندزبانه کامل / پرداخت ارزی
- پنل آنالیتیکس رشد

---

## ۶. فرض‌های بیزینسی MVP

- مصاحبه ۱:۱ است (یک candidate، یک interviewer، یک slot)
- زمان‌ها strictly UTC هستند
- اعتبار محصول از **قالب ارزیابی + immutability نمره** می‌آید، نه از برند interviewer alone
- مهارت‌های تأییدنشده قابل استفاده‌اند ولی Admin باید بتواند کاتالوگ را کنترل کند
- Verify عمومی می‌تواند بخشی از هویت را ناشناس کند؛ نمره، مهارت‌های ارزیابی‌شده و verdict badge نمایش داده می‌شود
- TrustScore / IsVerified در مدل هستند؛ فرایند پیچیده verification interviewer در MVP حداقل است

---

## ۷. معیار موفقیت MVP (Success Metrics)

### محصولی (باید سبز شوند)

- یک interviewer بتواند اسلات بسازد
- یک candidate بتواند همان اسلات را رزرو کند
- رزرو همزمان دو نفر روی یک اسلات → فقط یکی موفق
- interviewer بتواند دقیقاً یک‌بار scorecard را lock کند
- OverallScore مطابق فرمول ذخیره شود
- لینک verify بدون لاگین، همان نمره را نشان دهد

### بیزینسی اولیه (بعد از ترافیک واقعی)

| متریک | هدف اولیه پیشنهادی |
| --- | --- |
| Activation | ≥ ۴۰٪ interviewerهای ثبت‌نام‌شده حداقل ۱ اسلات بسازند |
| Booking completion | ≥ ۳۰٪ اسلات‌های ساخته‌شده رزرو شوند |
| Score submit rate | ≥ ۷۰٪ bookingهای Confirmed به Completed برسند |
| Share intent | ≥ ۲۰٪ completedها حداقل یک بار endpoint verify را باز کنند |

(اعداد فرض کار هستند؛ برای هدایت محصول، نه تعهد سرمایه‌گذاری.)

---

## ۸. تعریف Done برای MVP

MVP از نظر بیزینس **Done** است وقتی:

1. حلقه end-to-end بالا فقط با API (+ Swagger) قابل اجرا باشد
2. قوانین رزرو و امتیاز با تست واحد پوشش داده شده باشند
3. نتیجه بعد از submit قابل تغییر نباشد
4. یک لینک verify عمومی برای نمایش کارنامه وجود داشته باشد
5. Admin بتواند مهارت پیشنهادی را approve کند

UI زیبا، پرداخت، و deploy کامل API در cloud جزء Doneی MVP بیزینسی نیستند.
